# Nurtly – Roadmap

Status: Knowledge Base v1  
Confidence: Medium  
Last updated: 2026-05-31

## Purpose

This document describes the working roadmap for Nurtly.

It is not a fixed delivery plan. It should guide prioritization and help future contributors understand the intended development sequence.

## Roadmap Philosophy

Nurtly should grow in controlled stages.

The goal is not to build a large parenting platform immediately. The goal is to validate a calm, useful, parent-focused product and then expand based on evidence.

## Stage 0: Foundation

Status: In progress / partially completed

Purpose:

Prepare product direction, documentation, store materials, and technical foundations.

Includes:

- product vision
- knowledge base
- store listing copy
- release documentation
- sound artwork concepts
- MVP scope
- privacy assumptions
- initial repository structure

Success criteria:

- product direction is clear
- AI agents have context
- core documentation exists
- MVP scope is not chaotic

## Stage 1: MVP Build

Status: Planned / in progress depending on code state

Purpose:

Build a simple, calm, usable version of Nurtly.

Recommended modules:

- Home
- Sounds
- Journal
- Play
- Settings / Privacy
- Onboarding

### Stage 1A: Calm Home

Goals:

- introduce the product calmly
- provide clear navigation
- avoid dashboard overload

Candidate features:

- module shortcuts
- simple greeting
- recent or suggested action
- minimal visual clutter

### Stage 1B: Sounds MVP

Goals:

- provide immediate calming value
- support routines
- create a polished, premium-feeling module

Candidate features:

- sound list
- sound detail/player
- play/pause
- loop
- timer
- fade-out
- cover artwork

Known sound concepts:

- Soft rain
- Warm noise
- Quiet stream
- Evening crickets
- Room fan
- Dishwasher hum

### Stage 1C: Journal MVP

Goals:

- reduce mental load
- support daily care logging
- create repeat usage

Candidate features:

- add entry
- choose entry type
- timestamp
- optional note
- today timeline
- recent history

Open questions:

- exact entry types
- local-only vs cloud
- export timing
- whether multiple children are supported in MVP

### Stage 1D: Play MVP

Goals:

- give parents quick activity inspiration
- support quality parent-child interaction

Candidate features:

- curated activity list
- simple filters
- activity detail
- duration
- materials
- age range

Open questions:

- initial content size
- content source
- content review process
- language strategy

### Stage 1E: Privacy and Settings

Goals:

- build trust
- satisfy store requirements
- support transparency

Candidate features:

- privacy policy link
- data explanation
- language setting
- app version
- support/contact
- account/data deletion if account exists

## Stage 2: Store Readiness

Purpose:

Prepare for Google Play release and testing.

Includes:

- app description
- short description
- screenshots
- feature graphic
- privacy policy
- data safety form
- test track
- 20 testers if required
- release checklist

Existing docs:

docs/release

These should remain aligned with the knowledge base.

## Stage 3: MVP Validation

Purpose:

Learn which parts of Nurtly create real value.

Key questions:

- Do users understand the product?
- Do users return?
- Which module gets repeat use?
- Are Sounds enough to drive retention?
- Is Journal valuable or too much effort?
- Is Play used repeatedly?
- Does calm premium design resonate?
- Do users trust the app?

Potential metrics:

- onboarding completion
- sound plays
- timer usage
- journal entries created
- activity opens
- day 1 retention
- day 7 retention
- paywall interaction if monetization exists
- qualitative feedback

## Stage 4: Post-MVP Improvements

Purpose:

Improve what works after MVP validation.

Possible improvements:

### Journal

- better history
- search
- filters
- export
- summaries
- recurring patterns
- caregiver handoff

### Sounds

- favorites
- more sound packs
- premium sounds
- better player
- background playback improvements
- sleep/evening routines

### Play

- saved activities
- better filters
- activity packs
- recommendations
- seasonal activities
- personalization

### Home

- more useful daily summary
- gentle suggestions
- routine shortcuts

## Stage 5: Monetization

Purpose:

Test sustainable business model.

Possible monetization areas:

- premium sound packs
- premium activity packs
- advanced Journal
- export
- routines
- AI summaries
- subscription

Important:

Monetization should not break trust or make the free product useless.

## Stage 6: AI-Assisted Features

Purpose:

Use AI where it provides clear value and can be implemented safely.

Possible features:

- AI activity suggestions
- Journal summaries
- routine ideas
- personalized recommendations
- content assistant

Rules:

- no diagnosis
- no medical advice
- no unsafe claims
- privacy review required
- clear disclaimers
- guardrails required

## Stage 7: Scale and Expansion

Purpose:

Expand the product after validation.

Possible directions:

- more languages
- richer content library
- accounts and sync
- multi-caregiver support
- family sharing
- partnerships
- expert-reviewed content
- web companion
- RAG-powered internal product assistant

## Recommended Near-Term Sequence

1. Finish Knowledge Base v1.
2. Review current app state.
3. Define exact MVP modules.
4. Define Journal fields.
5. Define local/cloud storage model.
6. Finalize Sounds content.
7. Align store docs with product scope.
8. Build MVP.
9. Run internal testing.
10. Prepare Google Play test track.
11. Collect feedback.
12. Iterate.

## Roadmap Risks

- building too much before validation
- delaying launch due to over-polishing
- unclear monetization
- weak differentiation
- privacy complexity
- content maintenance burden
- AI feature safety risks
- app store compliance issues
- name/trademark risk

## Roadmap Rule

If a feature does not clearly support MVP validation, it should be considered post-MVP unless it is required for store approval, privacy, or technical stability.
