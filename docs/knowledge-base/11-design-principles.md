# Nurtly – Design Principles

Status: Knowledge Base v1  
Confidence: Medium-High  
Last updated: 2026-05-31

## Purpose

This document defines design principles for Nurtly.

It should guide UI design, visual assets, sound artwork, store screenshots, copywriting, animations, and future product decisions.

## Design Direction

Nurtly should feel:

- calm
- warm
- soft
- premium
- trustworthy
- safe
- supportive
- parent-oriented
- practical

Nurtly should not feel:

- childish
- loud
- clinical
- gamified
- chaotic
- overly technical
- AI-generated
- productivity-obsessed

## Audience

The app is designed for parents and caregivers.

This means the visual language should be adult-oriented.

It can be gentle and warm, but should not look like a children's game or cartoon toy.

## Core Visual Mood

Preferred mood:

- quiet evening
- warm home
- soft routine
- natural calm
- premium wellness
- gentle organization

Avoid mood:

- medical dashboard
- toy-like interface
- hyper-colorful parenting app
- corporate SaaS
- productivity tracker
- fitness streak app

## Color Direction

Preferred palette:

- muted sage green
- warm off-white
- soft grey-blue
- gentle beige
- warm neutral tones
- low contrast accents used carefully

Avoid:

- harsh red
- neon colors
- overly saturated palette
- high-pressure alert colors
- childish rainbow design

## Typography

Typography should support calm readability.

Recommended qualities:

- clean
- soft
- readable
- modern
- not overly playful
- not overly corporate

Text should be easy to read when the user is tired.

## Layout

Layouts should be spacious and clear.

Rules:

- avoid dense screens
- prioritize one clear primary action
- use strong visual hierarchy
- keep navigation predictable
- avoid overwhelming first-time users
- make common actions easy to reach

## Microcopy

Tone should be:

- supportive
- calm
- human
- concise
- non-judgmental
- reassuring

Avoid:

- guilt
- pressure
- fear
- overly cute language
- medical authority tone
- exaggerated promises

Examples of preferred tone:

- "Add a quick note"
- "Start a calming sound"
- "Find a simple activity"
- "Your day does not need to be perfect"

Avoid:

- "Do not break your streak"
- "You are behind"
- "Your child needs this"
- "Optimize your baby"

## Interaction Principles

Nurtly should be usable by tired parents.

Important:

- reduce typing
- support quick actions
- avoid long setup
- keep flows short
- use sensible defaults
- support one-handed use where possible
- avoid hidden gestures for important actions

## Empty States

Empty states should be calm and useful.

They should explain what the user can do without making them feel bad.

Good empty state:

"Nothing logged yet today. Add a note when something feels worth remembering."

Bad empty state:

"You have not completed any care logs today."

## Notifications

Notifications should be gentle and optional.

Avoid:

- guilt-based reminders
- excessive frequency
- urgency unless truly needed
- manipulative copy

Notification strategy should be reviewed carefully before launch.

## Sound Artwork Principles

Sound artwork should be:

- horizontal-friendly
- calm
- premium
- adult-oriented
- soft atmospheric digital illustration
- suitable for mobile audio player cards

Must avoid:

- text
- logos
- UI
- people
- babies
- children
- cartoon animals
- music notes
- headphones
- speaker icons
- clutter
- harsh contrast
- dramatic mood

Known artwork style:

- editorial wellness aesthetic
- gentle natural or home ambience
- muted sage green
- warm off-white
- soft grey-blue
- gentle beige
- rounded-corner friendly composition

## Store Asset Design

Store screenshots and feature graphics should communicate:

- calm support
- practical parenting help
- daily organization
- soothing routines
- trustworthy privacy-conscious positioning

Avoid:

- overpromising
- medical claims
- AI hype
- childish screenshots
- too much text

## Accessibility

Nurtly should follow accessibility-friendly design.

Important:

- readable font sizes
- sufficient contrast
- clear touch targets
- simple navigation
- screen-reader-conscious labels where applicable
- avoid relying only on color
- reduce motion where appropriate

## Design Risks

Risks:

- looking too generic
- looking too childish
- looking too medical
- overloading Home
- making Journal feel like a chore
- making Sounds feel like a generic white noise app
- making Play feel like a blog
- using AI-looking visuals
- inconsistent illustration style

## Design Review Checklist

Before approving a screen or asset, ask:

1. Does it feel calm?
2. Is it clearly for parents?
3. Is it simple enough for a tired user?
4. Is the primary action obvious?
5. Does it avoid guilt or pressure?
6. Does it fit the premium direction?
7. Does it avoid unnecessary child-facing visuals?
8. Does it respect privacy?
9. Does it reduce cognitive load?
10. Would this still feel trustworthy in an app store screenshot?
