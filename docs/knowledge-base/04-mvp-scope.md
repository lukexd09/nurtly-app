# Nurtly – MVP Scope

Status: Knowledge Base v1  
Confidence: Medium  
Last updated: 2026-05-31

## Purpose

This document defines the working MVP scope for Nurtly.

The MVP scope should remain narrow enough to launch, validate, and iterate. Nurtly should not try to become a complete parenting platform in the first release.

## MVP Philosophy

The MVP should prove that parents find value in a calm, practical parenting companion.

The first release should answer:

- Do users understand the product?
- Do users return to use it?
- Which module creates the most value?
- Are parents willing to use Nurtly as part of a routine?
- Does the calm positioning resonate?

## MVP Product Promise

The MVP should help parents:

- organize simple daily care information
- find calming sounds
- discover useful play ideas
- feel supported by a calm product experience

It should not attempt to solve every parenting problem.

## Core MVP Modules

## 1. Home

### Purpose

Home should act as the calm starting point of the app.

### MVP Scope

Home may include:

- greeting or calm intro
- quick access to Journal
- quick access to Sounds
- quick access to Play
- simple summary or prompt
- minimal navigation

### Out of Scope for MVP

- complex dashboards
- advanced personalization
- AI-generated daily insights
- heavy analytics views
- streaks or gamified progress

### Success Criteria

Home is successful if users can immediately understand what they can do next.

## 2. Journal

### Purpose

Journal should reduce mental load by helping parents record selected daily care events and observations.

### MVP Scope

Potential MVP Journal capabilities:

- add simple entry
- select entry type
- add time
- add optional note
- view today’s entries
- view recent history

Possible entry types:

- sleep
- feeding
- diaper
- health note
- mood / observation
- custom note

This exact list requires review before implementation.

### Important MVP Assumption

Journal should be simple and fast. It should not become a full clinical tracker.

### Out of Scope for MVP

- medical recommendations
- diagnostic interpretation
- complex charts
- multi-child advanced management
- caregiver collaboration
- pediatrician export
- AI summaries
- cloud sync unless already needed

### Success Criteria

Journal is successful if a tired parent can log an event in a few seconds and later understand what happened during the day.

## 3. Sounds

### Purpose

Sounds should provide calming audio experiences for parent-facing routines.

### MVP Scope

Sounds may include:

- list of calming sounds
- audio playback
- loop
- timer
- fade-out
- sound cover artwork
- simple player UI

Known sound concepts:

- Soft rain
- Warm noise
- Quiet stream
- Evening crickets
- Room fan
- Dishwasher hum

### Out of Scope for MVP

- user-uploaded sounds
- complex mixing
- AI-generated audio
- sleep analysis
- child-targeted entertainment
- social sharing

### Success Criteria

Sounds are successful if users can quickly start a calming sound and use it in an evening or rest routine.

## 4. Play

### Purpose

Play should provide simple activity ideas for parents and young children.

### MVP Scope

Play may include:

- curated activity list
- age or stage filter
- category filter
- simple activity detail
- short instructions
- required materials
- duration estimate

### Out of Scope for MVP

- large content marketplace
- social sharing
- user-generated content
- complex recommendations
- AI activity generation without review
- achievements or child scoring

### Success Criteria

Play is successful if parents can quickly find one useful activity without browsing endlessly.

## 5. Onboarding

### Purpose

Onboarding should introduce the product and collect only what is necessary.

### MVP Scope

Onboarding may include:

- short product introduction
- language selection if needed
- optional child-related setup
- privacy reassurance
- module introduction

### Privacy Assumptions

- child name should not be mandatory
- date of birth should not be mandatory unless required for age-based content
- users should understand what data is collected
- the app should avoid unnecessary friction

### Out of Scope for MVP

- long profile setup
- forced account creation unless technically required
- detailed child profile
- intrusive personalization

## MVP Non-Goals

The MVP should not include:

- medical advice
- diagnosis
- therapy claims
- social network
- parent community
- gamification
- complex AI assistant
- advanced analytics
- marketplace
- multi-caregiver sync unless later validated
- heavy cloud infrastructure unless required

## MVP Quality Bar

The MVP should feel:

- calm
- stable
- polished enough
- simple
- trustworthy
- safe for parents

It is better to launch fewer features with strong coherence than many unfinished modules.

## Store Readiness

MVP must consider:

- Google Play requirements
- app description
- screenshots
- feature graphic
- privacy policy
- data safety form
- 20-tester testing requirement if applicable
- store listing copy

Store release materials already exist in the repository under docs/release and should be kept aligned with this knowledge base.

## Validation Questions

MVP should help answer:

1. Which module do users open first?
2. Which module drives repeat usage?
3. Do users understand Nurtly’s value?
4. Does the calm design direction work?
5. Do users trust the app with parenting-related data?
6. Is Journal worth expanding?
7. Are Sounds enough to support a freemium model?
8. Is Play useful without heavy personalization?

## MVP Risk Areas

- Too broad scope
- Journal becoming too complex
- Sounds not being differentiated enough
- Play content requiring too much manual curation
- Privacy concerns around child data
- Weak monetization signal
- App store positioning being too vague
- Product looking like a generic parenting app

## Recommended MVP Priority

Recommended order:

1. Privacy-safe onboarding
2. Calm Home
3. Sounds
4. Journal basic logging
5. Play basic content
6. Store readiness
7. Analytics and feedback loop

This order can change based on technical progress.
